M5 · plan item

One Needs attention list, with a button for every finding

Today the dashboard and the bell read from two different places. The dashboard's Needs attention is built in the browser from the service and worker lists (app.js:1500-1708); the bell reads /api/collector-alerts and renders its own rows (app.js:4967-5015). So the dashboard can say "Nothing needs you" (app.js:1714) while the bell shows a red count. Several findings have no button at all: a device link (the catalog's device_link, e.g. services/bandwidth/earnapp.yml:47-52) still being retried only becomes a bell notice after a day (app/main.py:1392-1409), a quiet balance gets a muted note, and drift is one row per service per box (app.js:1575-1605).

The proposal: the server builds one list, GET /api/findings, from a new app/findings.py. Each finding has a stable id, a code, a severity, a subject, and typed actions (run, copy, open link, snooze, ignore). The dashboard panel, the bell, the CLI and an agent all read that one list and run the same actions.
