Add a box: a dialog that generates everything and waits live

A second box on a different IP is how the fleet earns more, and adding one is the step most likely to end in a terminal with no answer. The in-app snippet today has 3 of the 6 variables a remote worker needs, copies a loopback UI address no other machine can reach, sits in a closed <details> under everything else on Fleet, and never says whether the new box arrived.

Today

  • Find it: scroll past Boxes, Running costs and Proxies, open the last <details> (fleet.html:128-129). With the keyboard: about 30 Tabs from the top bar.
  • Fill it: 3 variables (fleet.html:137-139); the docs need 6 (docs/fleet.md:117-124): CASHPILOT_WORKER_URL, _WORKER_BIND_ADDR, _COMPOSE_DIR are missing, and the docs warn that without WORKER_URL the UI often cannot reach the worker (docs/fleet.md:133-134).
  • UI address: window.location.origin (fleet.html:171), which is http://127.0.0.1:8080 on a default install, because the UI is published on loopback only (docker-compose.yml:36).
  • Key: Reveal, then Copy the shared enrollment key, which stays valid on every future box (docs/fleet.md:137).
  • Then: 5+ terminal steps on the box (download, write .env, edit 6 lines, up, check logs), and the only sign of success is a new row appearing whenever Fleet next refreshes.

After

  • Find it: a + Add a box button in the Boxes header, n on Fleet, and "add box" in the palette (M3). A single-box fleet gets a one-line nudge.
  • Fill it: two fields. Everything else is generated: all 6 variables, the compose file pinned to this UI's version, a one-use join token that expires in 1 h.
  • UI address: chosen from addresses the UI can see, with a warning and the one-line fix when the UI only listens on loopback.
  • Then: 1 paste on the box. The dialog waits live, then runs 6 checks and shows the fix for any that fail, with Check again.
  • Terminal or agent: cashpilot box add box-c --print compose prints the same block; cashpilot box wait box-c --json streams the same checks.
Before · bottom of Fleet, details opened (screenshot of v2.1.1)
  • Loopback UI URL copied as is.
  • server-name is a placeholder to edit by hand.
  • No compose file, no docker command, no Unraid path.
  • Badge says "Configured", not "this box arrived".

Your UI listens on 127.0.0.1 only. Remote boxes cannot reach it.

The cashpilot-ui container is published on 127.0.0.1:8080, the safe default. box-c will not be able to call http://192.0.2.10:8080 until the UI is published there too, or put behind a reverse proxy.

Why loopback is the default
# On the machine running the UI, in the folder with its docker-compose.yml: echo 'CASHPILOT_BIND_ADDR=192.0.2.10' >> .env docker compose up -d

Publish on the LAN or VPN address only, never 0.0.0.0 on a machine with a public IP. This page reloads by itself once the UI answers on the new address.

Where the UI reaches box-c's worker. Left empty, the command finds box-c's first LAN address itself.
