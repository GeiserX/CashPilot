# 待领取的钱：在你失去收益之前提醒你 { #money-waiting-reminders-before-you-lose-earnings }

有些提供商会收回放置太久的钱。余额可能在
数月没有活动后过期。领取窗口可能会关闭。提供商可能在你的余额还在的时候
封禁账户、停止付款或关停。
CashPilot 已经读取了预见这些情况所需的大部分信息。仪表板上的
**Money waiting** (待领取的钱) 面板会显示要做什么、在什么时间之前做，
你的通知渠道也会在每个截止日期之前收到推送。

CashPilot 从不替你领取或提取任何东西。每条提醒都链接到
提供商自己的页面，由你在那里操作。

## 它会提醒你什么 { #what-it-reminds-you-about }

**来自提供商自身条款的规则。** 每条规则都引用了提供商的条款
或帮助页面，以及最近一次有人阅读它的日期。该行 **More** (更多) 菜单中的
**Source** (来源) 链接会打开它。

| 服务 | 提醒 | 时间 |
|---|---|---|
| Grass | 领取你的 Stage 2 USDC | 在 2027 年 1 月 22 日之前。未领取的部分由 Grass 保留。 |
| MystNodes | 领取上个月的奖励 | 每次月度分配后的 30 天内 |
| Honeygain | 提取你的余额 | 余额首次达到 $20 后的 24 个月 |
| Honeygain | 让一台设备保持共享，或进行一次付款 | 最后一次活动或付款后的 6 个月 |
| Repocket | 让一台设备保持共享，或提现 | 最后一次活动或付款后的 12 个月 |
| Bitping | 提取你的余额 | 最后一次提现后的 12 个月 |
| Salad | 赚取一些 Reward Points，或花掉你的余额 | 余额最后一次增长后的 12 个月。花掉其中一部分不会重置这个时间。 |

**提现。** 当余额达到提供商的
最低付款额时，CashPilot 会告诉你。这适用于它采集的每个服务，但
自动付款的服务除外。余额还必须至少值 $5，这样最低付款额只有 5 美分的
提供商不会在第一分钱时就来打扰你。如果提供商的
最低付款额更高，则以提供商的最低付款额为准。当 CashPilot 无法
换算最低付款额或余额时，它什么也不显示。它从不猜测
你可以提现。

**凭据过期。** 在已保存的令牌或 cookie 过期之前，你会收到推送。
CashPilot 使用凭据本身声明的过期日期。如果凭据没有声明，
CashPilot 就使用这类凭据的通常有效期，从你保存它的那天算起。
所有者已经能在 **Needs attention** (需要处理) 下看到它，
并有一个 **Renew** (续期) 按钮，所以面板不会重复显示。只有所有者会从 API 收到
凭据提醒，这与凭据健康检查相同。
被提供商拒绝的凭据已经出现在铃铛中并已推送过，
所以不会再次推送。

## 它涵盖哪些服务 { #which-services-it-covers }

提醒适用于你使用的服务：已部署的服务、你在 **Settings** (设置) 中设置为
外部的服务，或手机报告的应用。你删除的服务只要还有余额，
就仍然算在内，因为不活动计时从它停止时开始。
自定义服务和已停运的服务没有提醒。

## 日期与“或更早” { #dates-and-or-earlier }

活动计时从 CashPilot 记录的以下时间点开始计算：

- 余额最后一次增长的时间，
- 最后一次付款，
- 或第一条达到或超过最低付款额的读数。

有时计时在 CashPilot 的第一条读数之前就已经开始。这时真正的
截止日期可能比 CashPilot 能看到的更早，该行会显示
“2027 年 10 月 3 日或更早之前”。

CashPilot 会在 400 天后删除收益历史，而 Honeygain 的计时
长达 730 天。所以 CashPilot 会在第一次看到计时起点时就把它存下来，
并在其背后的历史被删除后继续保留。一次付款会重置
计时，除非提供商只计算赚取行为。Salad 就是其中之一：
付款后仍留有余额时，并不会重置它的 12 个月。

固定日期在过期后的第二天就会消失，因为钱已经没了。
逾期的计时会保留，并说明提供商可能已经把这笔钱
注销了。它会一直保留，直到你把它标记为完成或静音，或者直到一次付款
重置它。

## 你可以对提醒做什么 { #what-you-can-do-with-a-reminder }

所有者和编辑者能看到按钮。查看者只能看到提醒。只有所有者
可以处理凭据提醒。

- **Done** (完成)，或者对提现而言的 **Requested** (已申请)，会隐藏这条提醒。月度
  窗口会在下个月重新出现。如果 14 天后余额仍在，提现提醒会再出现一次，
  并询问付款是否已到账。这仍在大多数提供商给出的 60 天争议期内。
- **Snooze** (稍后提醒) 会把它隐藏一天或一周，并暂停它的推送。稍后提醒的时间
  永远不会超过截止日期前的最后一次警告。
- **More** (更多) 菜单中的 **Not for me** (不适用于我) 会静音一条提醒，或某个服务的
  所有提醒。一个例子：处于 JumpTask 模式的 Honeygain，此时余额不变
  是正常的。被静音的提醒列在面板底部，并带有
  **Unmute** (取消静音)。

这些选择由家庭成员共享。当一个人把提醒标记为完成时，它
对所有人都是完成的。每个选择都会连同做出选择的人的名字
记录在审计日志中。

## 推送 { #pushes }

提醒会发送到你为警报设置的渠道：ntfy、webhook 或 Telegram
（[配置](configuration.md)）。如果没有设置渠道，面板就是它们唯一
出现的地方。

- 每次警告推送一次。例如，Grass 会在其日期前 60、30、7 和 1 天推送。
  一条在日期前 5 天才首次出现的提醒只推送一次，此时还剩 5
  天。
- 推送只在 09:00 到 21:00 之间发出。CashPilot 先使用 **Settings** (设置) 中第一个所有者的
  时区，其次是容器的 `TZ`，最后是 UTC。夜间触发的警告
  会在 09:00 之后的第一次检查时发出。
- 当同时有超过 3 条推送到期时，你会改为收到一条摘要。这
  会在你升级的那天发生，此时所有超过最低付款额的余额会同时出现。
- 推送包含服务、要做的事、你会失去什么、日期以及
  提供商的链接。它从不包含余额、地址、设备 id 或
  工作节点名称。ntfy 主题可能是公开的。
- Webhook 负载带有 `kind: "obligation"`，这样 Home Assistant 及类似
  工具就能对它们进行路由。

## 致目录贡献者 { #for-catalog-contributors }

规则写在每个服务的 YAML 文件中，位于 `obligations:` 下。
`services/_schema.yml` 记录了各字段。只有当
提供商自己的条款或文档写明了某条规则，并且 CashPilot 能看到它所依赖的信号时，
才添加这条规则。规则的链接必须位于该服务自己的域名上，因为恰恰针对这些服务
存在虚假的领取网站。规则无效时，以及带日期的规则过期超过 30 天时，
CI 都会失败。
