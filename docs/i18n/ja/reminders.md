# 受け取り待ちのお金: 収益を失う前のリマインダー { #money-waiting-reminders-before-you-lose-earnings }

プロバイダーの中には、長く置かれたままのお金を回収してしまうところがあります。何か月も活動がないと
残高が失効することがあります。受け取りの期間が終わることがあります。残高が残っているうちに、
プロバイダーがアカウントを停止したり、支払いをやめたり、サービスを終了したりすることもあります。
CashPilot は、こうした事態を予見するのに必要な情報のほとんどをすでに読み取っています。ダッシュボードの
**Money waiting** (受け取り待ちのお金)パネルには、何をいつまでにすればよいかが表示され、
各期限の前には通知チャンネルにプッシュ通知が届きます。

CashPilot があなたの代わりに受け取りや出金をすることはありません。各リマインダーはプロバイダー自身の
ページにリンクしており、操作はそこで行います。

## 何をリマインドするか { #what-it-reminds-you-about }

**プロバイダー自身の規約にあるルール。** 各ルールは、プロバイダーの規約またはヘルプページと、
誰かが最後にそれを読んだ日付を引用しています。行の **More** (その他)メニューにある **Source** (出典)リンクで
それを開けます。

| サービス | リマインダー | 期限 |
|---|---|---|
| Grass | Stage 2 の USDC を受け取る | 2027 年 1 月 22 日まで。受け取られなかった分は Grass のものになります。 |
| MystNodes | 先月の報酬を受け取る | 毎月の配布から 30 日以内 |
| Honeygain | 残高を出金する | 残高が最初に $20 に達してから 24 か月後 |
| Honeygain | デバイスで共有を続けるか、支払いを受ける | 最後の活動または支払いから 6 か月後 |
| Repocket | デバイスで共有を続けるか、出金する | 最後の活動または支払いから 12 か月後 |
| Bitping | 残高を出金する | 最後の出金から 12 か月後 |
| Salad | Reward Points を稼ぐか、残高を使う | 残高が最後に増えてから 12 か月後。一部を使ってもこの期間はリセットされません。 |

**出金。** 残高がプロバイダーの最低支払額に達すると、CashPilot が知らせます。
これは、CashPilot が収益を収集するすべてのサービスに当てはまります。ただし、自動で支払われる
サービスは除きます。残高は少なくとも $5 の価値がある必要もあるので、最低額が 5 セントの
プロバイダーで最初の 1 セントから通知が来ることはありません。プロバイダーの最低支払額のほうが高い場合は、
プロバイダーの最低支払額が適用されます。CashPilot が最低額か残高を換算できない場合は、
何も表示しません。出金できると推測することはありません。

**認証情報の期限切れ。** 保存したトークンや Cookie が期限切れになる前に、プッシュ通知が届きます。
CashPilot は、認証情報そのものに書かれた有効期限を使います。何も書かれていない場合は、
その種類の認証情報の通常の有効期間を、保存した日から数えて使います。オーナーにはこれが
すでに **Needs attention** (要対応)の下に **Renew** (更新)ボタン付きで表示されるので、パネルでは繰り返しません。
API から認証情報のリマインダーを受け取るのはオーナーだけで、認証情報のヘルスチェックと同じです。
プロバイダーが拒否した認証情報は、すでにベルに表示され、プッシュ通知も済んでいるので、
もう一度プッシュされることはありません。

## 対象となるサービス { #which-services-it-covers }

リマインダーは、あなたが使っているサービスに適用されます。デプロイ済みのもの、**Settings** (設定)で
外部として設定したもの、またはスマートフォンが報告するアプリです。削除したサービスも、
残高がある間は対象に含まれます。活動がない期間の計測は、サービスが止まったときに始まるからです。
カスタムサービスと提供終了したサービスにはリマインダーはありません。

## 日付と「またはそれより前」 { #dates-and-or-earlier }

活動の期間は、CashPilot が記録したものから数えます。

- 残高が最後に増えたとき、
- 最後の支払い、
- または最低額以上になった最初の読み取り値。

計測の開始が CashPilot の最初の読み取りより前だったこともあります。その場合、本当の
期限は CashPilot から見えるより早いかもしれず、行には
「2027 年 10 月 3 日まで、またはそれより前」と表示されます。

CashPilot は収益の履歴を 400 日後に削除しますが、Honeygain の期間は
730 日です。そのため CashPilot は、各期間の開始を最初に見たときに保存し、
その元になった履歴が消えた後も保持します。支払いがあると期間はリセットされます。ただし、
プロバイダーが収益だけを数える場合は別です。Salad がその 1 つです。残高が残る支払いでは、
12 か月の期間はリセットされません。

固定の日付は、その日が過ぎた翌日に消えます。お金はもうなくなっているからです。
期限を過ぎた期間は残り、プロバイダーがすでにそのお金を無効にしたかもしれないと表示します。
完了にするかミュートするまで、または支払いでリセットされるまで残ります。

## リマインダーでできること { #what-you-can-do-with-a-reminder }

ボタンが表示されるのはオーナーと編集者です。閲覧者にはリマインダーだけが表示されます。
認証情報のリマインダーを操作できるのはオーナーだけです。

- **Done** (完了)、または出金の場合は **Requested** (申請済み)で、このリマインダーを非表示にします。
  毎月の期間は翌月にまた表示されます。出金のリマインダーは、14 日後にまだ残高が残っていれば 1 回だけまた表示され、
  支払いが届いたかどうかを尋ねます。これは、多くのプロバイダーが設けている 60 日間の異議申し立て期間の内側です。
- **Snooze** (スヌーズ)は、1 日または 1 週間非表示にし、その間のプッシュ通知を止めます。スヌーズが
  期限前の最後の警告を越えて続くことはありません。
- **More** (その他)メニューの **Not for me** (自分には不要)は、1 つのリマインダー、またはあるサービスの
  すべてのリマインダーをミュートします。一例は JumpTask モードの Honeygain で、残高が増えないのが
  ふつうです。ミュートしたリマインダーは、パネルの下部に **Unmute** (ミュート解除)付きで一覧表示されます。

これらの選択は世帯で共有されます。誰か 1 人がリマインダーを完了にすると、全員にとって
完了になります。各選択は、それを行った人の名前とともに監査ログに記録されます。

## プッシュ通知 { #pushes }

リマインダーは、アラート用に設定したチャンネル(ntfy、Webhook、Telegram)に送られます
([設定](configuration.md))。チャンネルが設定されていない場合、表示されるのはパネルだけです。

- 警告ごとにプッシュ通知は 1 回です。たとえば Grass は、期日の 60 日前、30 日前、7 日前、1 日前に
  プッシュします。期日の 5 日前に初めて見つかったリマインダーは、残り 5 日として 1 回だけ
  プッシュします。
- プッシュ通知が送られるのは 09:00 から 21:00 の間だけです。CashPilot は、**Settings** (設定)にある最初のオーナーの
  タイムゾーンを使い、なければコンテナの `TZ`、それもなければ UTC を使います。夜間に到達した警告は、
  09:00 以降の最初のチェックで送られます。
- 一度に 3 件を超えるプッシュ通知が届く予定のときは、代わりに要約が 1 件届きます。これは
  アップグレードした日に起こります。最低額を超えるすべての残高が一度に現れるからです。
- プッシュ通知には、サービス、すべきこと、失うもの、日付、プロバイダーのリンクが含まれます。
  残高、アドレス、デバイス ID、ワーカーの名前が含まれることはありません。ntfy のトピックは公開されている場合があるからです。
- Webhook のペイロードには `kind: "obligation"` が含まれるので、Home Assistant などの
  ツールで振り分けられます。

## カタログの貢献者へ { #for-catalog-contributors }

ルールは各サービスの YAML ファイルの `obligations:` の下にあります。
フィールドは `services/_schema.yml` に記載されています。ルールを追加するのは、
プロバイダー自身の規約やドキュメントにそう書かれていて、かつ CashPilot がそのルールの
根拠となるシグナルを見られる場合だけにしてください。ルールのリンクはそのサービス自身のドメインに
なければなりません。まさにこうしたサービスを狙った偽の受け取りサイトが存在するからです。CI は、無効なルールと、
日付が 30 日以上過ぎた日付付きのルールで失敗します。
